# Как устроен бот

`index.js` загружает окружение, запускает grammY runner и обрабатывает остановку процесса. Импорт `bot/createBot.js` не запускает polling: этот модуль собирает зависимости и регистрирует обработчики.

## Путь запроса

1. `bot/linkHandler.js` извлекает обычную или скрытую ссылку и просит фабрику определить платформу.
2. `downloaders/DownloaderFactory.js` проверяет HTTP(S) и точные границы домена. Например, `youtube.com.evil.example` не является YouTube.
3. `BaseDownloader` получает информацию через `services/YtDlp.js`. Подклассы определяют только отличия YouTube, Instagram и TikTok. Повтор запросов вынесен в `utils/retry.js` и ограничен временными сетевыми ошибками.
4. `SelectionStore` хранит выбор по паре чат + пользователь. Новая ссылка заменяет старое меню; поздний ответ старого запроса не меняет новый выбор. Меню истекает через 15 минут.
5. `bot/callbackHandler.js` проверяет кнопку и атомарно забирает выбор до первого `await`. Это предотвращает двойной запуск при быстрых повторных нажатиях.
6. `DownloadQueue` допускает две одновременные загрузки. Новая задача стартует после освобождения слота, без опроса таймером. В очередь записан владелец задачи, поэтому `/queue` показывает его действительную позицию.
7. `DownloadService` создаёт отдельный временный каталог, скачивает файл и проверяет его размер. `bot/sendMedia.js` выбирает `sendVideo`, `sendAudio` или `sendDocument`. `bot/downloadJob.js` очищает каталог в `finally`, включая ошибку отправки.

## Где менять поведение

| Задача | Модуль |
| --- | --- |
| Текст, кнопки, сообщения об ошибках | `services/UIService.js` |
| Разрешения, форматы, поддерживаемые домены | `config/platforms.js` |
| URL Telegram API и лимит файла | `config/telegram.js` |
| Специфика конкретной платформы | соответствующий класс в `downloaders/` |
| Запуск yt-dlp и cookies | `services/YtDlp.js` |
| Очередь и параллельность загрузок | `services/DownloadQueue.js` |
| Состояние и срок жизни меню | `services/SelectionStore.js` |
| Сценарии Telegram | небольшие обработчики в `bot/` |

## Тестовые границы

Функциональные тесты вызывают `bot.handleUpdate` с реалистичными Telegram-обновлениями. В них работают реальные обработчики, клавиатура, выбор качества, очередь, сохранение и удаление файлов. Подменены две внешние границы: процесс скачивания из интернета и транспорт Telegram.

Отдельный тест запускает настоящий дочерний процесс по пути с пробелами. Реальные медиа и работа интерфейса Telegram проверяются отдельно по `docs/QA.md`.

## Ограничения

Состояние меню и очередь находятся в памяти одного процесса. Перезапуск требует новой ссылки; распределённая очередь и возобновление задач не реализованы. При принудительном завершении процесса временные файлы могут остаться: обычная остановка через Ctrl+C ожидает завершения текущих задач. Runner одновременно обрабатывает до 20 обновлений; лимит двух загрузок действует отдельно.
